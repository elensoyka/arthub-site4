# ArtHub OS — запуск непрерывной синхронизации календарей (v0.1)

Дата: 14 ноября 2026, часовой пояс Asia/Tbilisi.

## Что уже работает без установки скрипта
- Google-таблица «ArtHub OS — Threads | редакционный календарь»:
  https://docs.google.com/spreadsheets/d/1aSjec3-1le6VEdkyeacWyb8_VtPWAX3AhgUOZqHXbYc/edit
- Вкладка **События** — единственный ввод фактов.
- Вкладка **Автоплан · кампании** — формулы, которые автоматически перестраивают шесть шагов продвижения для каждого из первых 25 событий. Это шаблонные **черновики**, не готовые посты и не автопубликация.
- Вкладка **Пульт · статус системы** — честное состояние интеграций и конфликты.
- Напоминания ChatGPT 09:00/13:00/18:00 по Тбилиси используют новую вкладку.

## Один раз включить автоматическое бронирование календарей (нужно действие владельца)
1. Откройте Google-таблицу в браузере на компьютере.
2. Выберите **Расширения → Apps Script**. Если проект уже существует, добавьте новый файл, не удаляя существующий код.
3. Скопируйте код из [ArtHubCalendarSync.gs](../automation/ArtHubCalendarSync.gs) в редактор Apps Script и сохраните.
4. В выпадающем списке функций выберите **installArthubTriggers** и нажмите **Run / Выполнить**; подтвердите разрешения для этой таблицы и Google Calendar.
5. Вернитесь к вкладке **События**. В нужной строке заполните:
   - **R «Подтвердить бронь»** = Подтверждено
   - **S «Помещение для брони»** = Зал / Мастерская / Театр / Кухня / Коворкинг / Выставки | ArtHub
   - **T «Длительность (мин)»** = число, например 90.
6. После этого **U** получит Google Calendar Event ID, а **V** — статус «Синхронизировано» или понятное предупреждение.

## Защита
- Строки со статусом «Черновик» никогда не создают брони.
- Скрипт сверяет занятость комнаты и не создаёт запись при конфликте.
- Запись можно обновлять без дубликата благодаря сохранённому U (Calendar Event ID).
- Автопубликация сайта, Threads и Instagram не включается этим скриптом.
- Скрипт не отправляет письма участникам и не подтверждает оплаты.
- При смене помещения уже синхронизированного события сначала нужно вручную перенести или отменить прежнюю запись; скрипт не перемещает её между календарями автоматически.
- Снятие подтверждения в R останавливает дальнейшие изменения, но не удаляет ранее созданное событие (преднамеренная защита от случайных отмен).

## Текущий блокер — подтверждения по мероприятиям
Нужно указать конкретные **помещение** и **длительность** лекций Ксении (16 и 19 ноября) и Pitch Night (18 ноября). Для Pitch Night время 19:00 восстановлено из прежних обсуждений; скриншот не обнаружен.

## Дальнейшая интеграция
Следующая версия автоматизации — публичная выдача только подтверждённых событий из единой базы в ArtHub Alive, без раскрытия заявок и рабочих заметок. Требует отдельной настройки безопасного серверного источника данных и проверки Cloudflare.

## Проверяемый результат
После установки при заполнении новой строки «События» должны автоматически появиться 6 строк в «Автоплан · кампании». Если R подтверждено, заполнены S/T и нет конфликта, календарная запись создаётся и её ID фиксируется в U. После изменения времени запись в Google Calendar обновляется по тому же ID.
